## 协议与可靠性修复

- 五端 PTP/IP 心跳不再重复发送 `OpenSession(0x1002)`，改为 event TCP 上的
  `ProbeRequest/ProbeResponse`（type 13/14）；常驻 reader 同时响应相机主动探测并
  排空 type 8 事件。
- Apple、HarmonyOS 与 Windows 把 command TCP 的请求、完整数据相位和最终响应纳入
  同一事务串行门；Android 保留既有实例同步边界，避免实时取景、参数、文件与快门
  并发时互相读取响应。
- `GetDeviceInfo(0x1001)` 恢复无参数请求，并按 PIMA 15740 的 PTP STR 与 AUINT16
  解析 Manufacturer；四端都校验 OperationResponse 的 transaction ID。
- data-out 改为 `StartData(tx,totalLength) → EndData(tx,data)`；HarmonyOS 同时补回
  `SetDevicePropValue` 的属性码参数。
- Android 增加 `ACCESS_NETWORK_STATE`，HarmonyOS 增加 `GET_NETWORK_INFO`。
  Windows 每轮重连设 12 秒上限，完成厂商、取景与参数恢复后才退出重连态；HarmonyOS
  会先关闭旧双通道，再调度新连接。
- Apple、HarmonyOS、Windows 以 session generation 隔离断开前后的 writer/握手；
  Android 也用连接代际阻止已取消的初连/重连或本机相机回调重新发布会话；UI 线程
  先发布取消并通过无事务锁的 abort 立即打断 socket，完整状态复位再交给相机执行器。
  手动取消不会被在途重连复活，半握手会清理双通道，
  command-only 传输失败也会让后续心跳进入统一重连。data-in 支持未知长度哨兵并
  核验已知长度。

## 连接体验改进

- iOS/iPadOS、Android、HarmonyOS、macOS、Windows 的顶层连接管理均直接呈现
  Wi‑Fi/PTP‑IP；空闲态进入既有配置，失败态可直接重试，不再要求用户先从文件库
  猜测入口。
- 主动作随真实状态切换为取消连接、停止重连、断开和重试。连接与重连显示原生
  进度，模式、IP 与端口在活跃/已连接时锁定，恢复提示明确要求检查当前 Wi‑Fi、
  相机 PTP/IP、IP 地址和端口。
- 全局拍摄状态覆盖 Wi‑Fi 连接中、重连中和失败。Windows 快门、取景、LIVE、录像
  与相机存储统一使用 ready 门禁，进入重连即禁用，完成厂商识别、取景、参数和
  监看恢复后才重新启用。
- Android、HarmonyOS 与 Windows 使用 Wi‑Fi 专属错误状态，USB/本机相机失败不会
  污染 Wi‑Fi 卡；退出登录会清理旧错误。HarmonyOS 连接面板在小屏、横屏和分屏下
  可滚动；Windows 从顶层入口切入文件库后会定位并聚焦 Wi‑Fi 地址输入。
- Apple 动态操作标题与 Windows 建立、恢复、停止重连和断开错误均使用稳定三语
  资源；原始 Windows 协议异常只保留在诊断日志。五端启动公告统一说明 1.5.14
  仍是未发布的本地候选。
