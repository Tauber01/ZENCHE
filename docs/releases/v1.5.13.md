# 帧澈 ZENCHE 1.5.13 发布说明

> 发布日期：2026-08-12
> 版本：`1.5.13 / build 40`
> 发布范围：GitHub Release
> 官网自动更新：继续提供 `1.5.10 / build 37`，本次未切换生产清单

## 本次更新

1.5.13 为 iOS/iPadOS、Android、HarmonyOS、macOS 与 Windows 增加统一的“下载到本地”能力。现在可以把以下内容另存到自己选择的位置：

- 联机拍摄和外录产生的照片或视频；
- 从相机存储卡下载到 ZENCHE 文件库的文件；
- AI 修图与 AI 生图结果；
- 专业显影和其他编辑流程生成的新副本。

五端文件库均提供统一入口；支持应用内预览的页面也有快捷入口，AI 与专业显影工作区提供直达操作。移动端原有的“保存到系统相册”继续独立保留。

## 文件安全与保存行为

- 导出只创建副本，不移动、删除或原位修改 ZENCHE 文件库中的源文件。
- AI 与专业显影的直达流程会先生成新的文件库副本，再打开系统保存界面。macOS 与 Windows 的 AI 修图也改为始终创建新文件，不再覆盖当前原图。
- iOS/iPadOS 使用系统文档导出界面，Android 使用 Storage Access Framework，HarmonyOS 使用 DocumentViewPicker，macOS 使用 NSSavePanel，Windows 使用 SaveFileDialog。保存位置、文件名与同名覆盖确认由操作系统负责。
- 取消保存不会显示成功或错误。只有复制和写入完成、目标文件大小校验通过后才报告成功。
- 失败时会清理本次临时文件；Android 与 HarmonyOS 会尽力删除文档提供器中的不完整目标。跨提供器通常不支持事务重命名，因此移动端文档提供器写入不承诺严格原子提交。
- 桌面端在目标同目录写入临时文件，完成同步和大小校验后再替换或同卷移动。macOS 通过文件资源标识、Windows 通过卷序列号与文件索引复核目标，拒绝符号链接、Finder alias、junction 或 hardlink 指回源文件。大文件复制在后台执行。
- Android 会在系统保存界面打开期间保留待导出的库内相对路径，Activity 重建后仍可恢复；写入前通过设备号与 inode 拒绝目标指回源文件，`fsync` 后再读取目标实际大小。HarmonyOS 的复制、同步与大小校验通过 TaskPool 执行。
- 导出保留原文件字节和扩展名，不重新编码 JPEG、RAW 或视频。五端文件库统一识别 JPG/JPEG、HEIF/HEIC、PNG、TIF/TIFF、NEF/NRW、ARW、CR2/CR3、MOV/MP4/M4V 与 AVI；能否直接预览仍取决于平台解码能力。

## 相机与兼容性

- 本版本不增加或删除相机档案，也不改变 USB/PTP、PTP/IP、实时监看、拍摄或外录协议。
- 现有 Nikon、Sony、Canon 注册表与各平台能力边界保持不变。相机档案表示应用能够识别设备并选择相应参数范围，不代表所有机身、固件、镜头、线材和主机组合均已通过实机验证。
- “下载到本地”覆盖已经进入 ZENCHE 文件库的受支持 JPEG、RAW 与视频文件。

## 签名与安装边界

- **Android**：APK 使用 v2 Android Debug 证书；证书 SHA-256 为 `45499c18366356314c10ad8a98939908e47855fb6ba7fc21fe8a809549c7df3c`。这是社区调试签名，不是商店或正式发布证书。
- **iOS / iPadOS**：IPA 使用 `CODE_SIGNING_ALLOWED=NO` 构建，不含 Provisioning Profile 或代码签名，不能直接安装；需按自己的开发者团队与设备重新签名。
- **HarmonyOS**：项目未配置 `signingConfigs`，HAP 构建日志明确跳过签名；真机安装前需要有效的开发者签名与 Profile。
- **macOS**：应用为 ad-hoc 签名，DMG 未公证。应用深度严格验签与 DMG 校验通过，但没有完成 Gatekeeper 或真实安装验收。
- **Windows**：Setup 与主程序均无 Authenticode，PE Security Directory 为 0。两个 Windows 包由 macOS 主机交叉构建；这不等同于真实 Windows 启动、安装、升级、驱动或 SmartScreen 验收。
