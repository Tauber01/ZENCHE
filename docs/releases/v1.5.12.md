## 本次变更

- 修复 Windows 启动阶段的空引用崩溃。WPF 在 `InitializeComponent()` 构造命名控件树时会同步触发 XAML 默认选中事件；曝光模式曾在 `ShutterBox`、光圈和 ISO 等后置控件创建前刷新整组可用性，形成 `SetParameterAvailability → UpdateExposureAvailability → ExposureModeBox_SelectionChanged` 空引用链。
- 曝光模式处理器现在会在初始化期间先于 `UpdateExposureAvailability()` 返回；视频快门模式会先保存安全的 XAML 预选值，再于 `ConfigureShutterControl()` 前返回。共享参数处理器也把 `UpdateExposureReadout()` 移到初始化门禁之后，作为同阶段防御性加固。
- 完整界面加载后，构造器仍按原流程执行 `ConfigureShutterControl(false)`、结束初始化门禁并更新曝光读数；本次没有改变相机控制协议、文件格式或其他平台功能。
- 新增三条 Windows 启动顺序回归契约，锁定 `_initializing` 初值、事件连接、默认选中项、控件声明顺序、危险调用前的立即返回以及完整控件树加载后的恢复路径。
- Android、HarmonyOS、iOS/iPadOS、macOS 与 Windows 的版本元数据、运行时版本回退值和中英日启动公告统一到 `1.5.12 / build 39`。六个安装包均由当前冻结候选重新构建，没有复用或改名 1.5.11 资产。
- 构建总脚本不再在读取 `package.json` 失败时静默回退到 1.5.3，避免未来把安装包归档到错误版本。

## 安装与能力边界

- Android 使用开发环境 Debug 证书；设备上的旧包若使用不同证书，不能直接覆盖安装。
- iOS / iPadOS IPA 与 HarmonyOS HAP 未签名，需要各平台有效证书和描述文件/Profile。
- macOS 为 ad-hoc 签名且未公证，Gatekeeper 可能阻止首次打开。
- Windows 没有 Authenticode，SmartScreen 可能提示未知发布者。两包由 macOS 交叉构建；自动化、WPF 编译、NSIS 和压缩结构通过不等于真实 Windows 已验收。
- 真实 Windows STA/BAML 冷启动、主窗口显示、曝光与视频快门切换、安装、升级、卸载、驱动占用/权限及 SmartScreen 仍需 Windows 实机验证。
- 其他既有真机边界不变，包括 Nikon Z50 繁忙恢复、OPPO Camera2 降级、移动端系统照片权限/iCloud/另存、真实 AI 服务、桌面拖拽/多显示器/DPI、辅助功能和长时间性能。
- GitHub 1.5.12 不会由官网自动更新主动推送给现有用户；生产清单继续提供 1.5.10 / build 37。

## 校验方法

在安装包所在目录执行：

```sh
shasum -a 256 -c ZENCHE-1.5.12-android.apk.sha256
shasum -a 256 -c ZENCHE-1.5.12-ios-unsigned.ipa.sha256
shasum -a 256 -c ZENCHE-1.5.12-HarmonyOS.hap.sha256
shasum -a 256 -c ZENCHE-1.5.12-macOS-arm64.dmg.sha256
shasum -a 256 -c ZENCHE-1.5.12-Windows-x64-Setup.exe.sha256
shasum -a 256 -c ZENCHE-1.5.12-Windows-x64.zip.sha256
```

桌面工作区与登录操作见 `docs/DESKTOP_WORKSPACE_LAYOUT.md`。
