# 帧澈 ZENCHE v1.4.0

发布日期：2026-08-02

## 版本亮点

v1.4.0 重点修复 AI 修图结果与原图无关、调用 AI 未扣除次数两个问题，并把修图与生图的文件语义在五个原生平台统一：AI 修图成功后覆盖当前原图，AI 生图始终另存为新文件。

## AI 原图链路修复

- 客户端将当前选中照片编码为完整 `data:image/...;base64,...` 数据 URL。
- 私有代理改用 Grsai 正式接口 `POST /v1/api/generate`，将原图放入上游要求的 `images` 数组，不再使用无效的 `input_image` 字段。
- 代理使用 `replyType: "async"`，轮询 `/v1/api/result?id=...`，等待实际任务结果后才返回图片。
- 端到端验证返回 HTTP 200、`X-ZENCHE-Remaining: 99` 和有效 JPEG（约 509 KB，1024x1024），确认上游确实收到原图。

## 次数扣减与文件行为

- AI 次数由服务器权威扣减，通过 `X-ZENCHE-Remaining` 返回剩余次数；五端成功后同步本地显示。
- 上游失败、超时或保存失败时回滚预扣次数，失败请求不消耗额度。
- 修图结果写入临时文件，经校验后原子替换当前原图，同时更新图库记录、XMP 和 SHA-256 清单。
- 生图结果继续使用新的 `ai_generated_*.jpg` 文件名保存，不覆盖用户现有照片。

## 五端变化

- iOS / iPadOS：SwiftUI 编辑器和 PhotoKit 文件记录同步更新，生成 unsigned IPA。
- Android：Java 原生编辑器读取服务端剩余次数，修图临时写入后原子替换原图，生图保存独立新文件。
- HarmonyOS：ArkUI/ArkTS 新增图库原子替换与回滚路径，生成 unsigned HAP。
- macOS：SwiftUI/AppKit 编辑器更新文件记录、XMP 和 SHA-256，生成 ad-hoc 签名、未公证 DMG。
- Windows：WPF 使用临时文件和 `File.Replace` 覆盖原图，服务器剩余次数持久化，生成 NSIS 安装器和便携 ZIP。
- 五端公告、中文/英文/日文资源和版本号均同步到 `1.4.0 / build 23`。

## 相机与编辑器稳定性

- 保留并对齐 Nikon EXPEED 5/6/7、Sony α 和 Canon EOS R 档案与 Vendor ID 过滤。
- 改善 Nikon / Sony / Canon 识别、PTP 拍摄忙状态重试、实时取景停止后的就绪等待，以及专业编辑状态保持。

## 包与签名状态

- macOS：Apple Silicon DMG，ad-hoc 签名，未公证。
- Android：debug 证书签名 APK，适合侧载验证。
- HarmonyOS：unsigned HAP；真机安装需要开发者证书和 Profile。
- iOS / iPadOS：unsigned IPA；安装前必须使用 Apple Developer 证书重新签名。
- Windows：x64 NSIS Setup.exe 和便携 ZIP；未使用商业代码签名证书，Windows 真机安装、驱动和 SmartScreen 验收仍需补做。

## 已知限制

- AI 代理是私有生产服务，不包含在公开仓库；客户端继续保留旧代理配置读取兼容，但不提供可编辑服务器地址。
- AI 修图需要网络和有效激活码；上游服务不可用时请求失败且不消耗次数。
- iOS、HarmonyOS 包未签名；macOS 未公证；Windows 未使用商业签名证书。
- Sony / Canon 及部分 Nikon 机型仍需更多不同固件、镜头、线材和主机的真实硬件验收。
- 官网当前使用 `http://zenche.top/` 兑换入口，公网 TLS、MirrorChyan 资源映射和商店级分发仍是后续工作。

## 升级指导

1. 从本 Release 下载目标平台包及对应 `.sha256` 文件。
2. 安装前校验 SHA-256；Windows 便携版请保持 `libusb-1.0.dll` 与可执行文件同目录。
3. AI 修图前确认编辑器中已选择正确照片；成功后会覆盖该原图，重要素材请先保留相机存储卡或导出备份。
4. AI 生图会生成独立的新文件，不会覆盖已有照片。
5. HarmonyOS 与 iOS 安装前完成平台签名；Windows 首次使用按文档配置 WinUSB/libusb 驱动。
